# Запуск без Root и через Shizuku

## Что реально возможно

В upstream DroidVM есть два VMM backend (crosvm и QEMU), а для QEMU документирован режим **Software emulation**. Это полезный запасной путь, если ядро не предоставляет аппаратный гипервизор. Но он не равен режиму «без Root»: текущая архитектура DroidVM запускает фоновый демон `droidvmd` с Root-доступом. Само переключение на QEMU Software Emulation не убирает эту зависимость.

Shizuku предоставляет приложениям интерфейс для выполнения части операций с идентичностью Android shell. Это не Root и не способ автоматически открыть приложению закрытые узлы ядра. Если `/dev/kvm`, `/dev/gunyah` или `/dev/gzvm` недоступен shell-пользователю, Shizuku сам по себе не выдаст доступ к гипервизору.

Android Virtualization Framework (AVF) также не является универсальной заменой KVM для DroidVM. Его API для управления VM — системный API с ограниченным разрешением `MANAGE_VIRTUAL_MACHINE`; он предназначен для AVF/Microdroid и не запускает автоматически произвольную Windows VM через DroidVM. См. [документацию AOSP по AVF](https://android.googlesource.com/platform/packages/modules/Virtualization/+/HEAD/libs/framework-virtualization/README.md).

## Проверка на планшете без Root

Скрипт `scripts/check-unrooted.sh` только читает свойства Android, наличие устройств виртуализации и доступ к ним от имени текущего процесса. Он не меняет настройки и не требует Root.

Через ADB:

```sh
adb push scripts/check-unrooted.sh /data/local/tmp/check-unrooted.sh
adb shell sh /data/local/tmp/check-unrooted.sh
```

Или запусти файл в терминале Android от обычного пользователя. Для проверки именно Shizuku запусти те же команды через терминал/интерфейс, который выполняет команды с Shizuku, и пришли оба результата: обычный запуск и Shizuku.

## Как трактовать результат

- Если узел гипервизора существует и доступен обычному UID приложения, это хороший признак, но не доказательство, что DroidVM сможет создать VM.
- Если узел доступен только Root, Shizuku не следует считать обходом этого ограничения.
- Если гипервизор отсутствует, остаётся исследовать QEMU TCG (software emulation). Это медленный режим, и в текущем DroidVM Root-зависимый демон всё равно остаётся отдельным блокером.
- Если установлен Shizuku, это лишь подтверждает наличие приложения. Для фактической интеграции нужна поддержка Shizuku в самом приложении и отдельная проверка всех операций демона.

## Что ещё требуется для настоящего rootless APK

Нужна переработка upstream-движка: запуск QEMU как процесса приложения без Root, перенос управления VM из Root-демона в обычный процесс, безопасная работа с каталогами/образами и проверка сетевых функций. Команды Shizuku можно использовать только там, где Android shell действительно имеет необходимые права. Нельзя обещать, что это позволит использовать гипервизор.

Не устанавливай случайные kernel-модули и не прошивай boot.img ради этой проверки.
